# CARE — Calibrated Abstaining RAG Evaluator

A Retrieval-Augmented Generation system that knows when it doesn't know. Instead of always producing a confident-sounding answer, this system quantifies its own uncertainty using three independent signals, empirically validates that those signals actually correlate with correctness, and explicitly answers, hedges, or abstains based on calibrated confidence — rather than guessing and hoping.


---

## The problem

Most RAG demos optimize for "give an answer." They rarely ask whether the system *should* answer. A retriever with no good matches, or a generator working from ambiguous context, will still confidently produce fluent, wrong text — and a user has no way to tell the difference between a well-grounded answer and a hallucinated one.

This project builds a RAG pipeline that:
1. Produces three independent confidence signals across retrieval, reranking, and generation
2. Empirically validates whether those signals actually predict correctness (they do — see Finding #3 below)
3. Uses that validation to set data-driven thresholds for answering, hedging, or abstaining

---

## Architecture

```
Query
  │
  ▼
Bi-encoder retrieval (FAISS, all-MiniLM-L6-v2)  →  Signal #1: retrieval confidence
  │                                                   (normalized score gap + top score)
  ▼
Cross-encoder reranking (ms-marco-MiniLM-L-6-v2)  →  Signal #2: rerank confidence
  │                                                   (same gap+score logic, sigmoid-squashed)
  ▼
LLM generation, sampled 5x (Groq, gpt-oss-20b)  →  Signal #3: self-consistency confidence
  │                                                   (fraction of samples agreeing on majority answer)
  ▼
Combined confidence = equal-weighted average of the three signals
  │
  ▼
Decision: ANSWER (≥0.60) / HEDGE (0.40–0.60) / ABSTAIN (<0.40)
```

Each signal is independent, catching a different failure mode:
- **Retrieval confidence** — is there a clear best-matching passage, or is nothing in the corpus relevant?
- **Rerank confidence** — does a second, jointly-conditioned model agree with the retriever's ranking?
- **Self-consistency** — does the LLM produce the same answer across multiple samples, or does it waver?

## Key finding #1: a single confidence signal isn't trustworthy alone

Initial testing used **normalized score gap** (the relative difference between the top-1 and top-2 retrieval scores) as a standalone confidence signal. On real test queries, a gibberish query ("purple elephant quantum sandwich Tuesday") produced a *higher* confidence score (0.135) than a genuine, verifiably-answerable question about the Seine ("What river runs through Paris?", 0.025) — because gap alone is blind to absolute score magnitude. A corpus can produce a large gap purely from noise when nothing is actually relevant.

**Fix:** combined the gap with the absolute top-1 similarity score. This corrected the ordering on manual probes, but the deeper lesson — a single signal conflates different failure modes — is what motivated combining three independent signals rather than trusting any one.

## Key finding #2: the system is systematically underconfident

Running the full pipeline over a 76-question stratified evaluation set (balanced answerable/unanswerable, sampled from SQuAD 2.0 with a fixed random seed for reproducibility) and building a reliability diagram showed:

| Confidence bin | n | Avg. confidence | Avg. accuracy |
|---|---|---|---|
| 0.4–0.6 | 30 | 0.510 | 0.633 |
| 0.6–0.8 | 39 | 0.695 | 0.872 |
| 0.8–1.0 | 4 | 0.817 | 1.000 |

**Expected Calibration Error (ECE): 0.1545.** Every populated bin showed accuracy exceeding stated confidence — the system never claims more than ~82% confidence even when it's right 100% of the time. Traced to equal-weighted averaging of three signals that individually rarely approach 1.0, which mathematically caps the combined score below what the evidence actually supports.

## Key finding #3: recalibration fixed the average but broke discrimination

Applied Platt scaling (a standard, minimal-parameter logistic recalibration) to correct the underconfidence. ECE dropped sharply — **0.1545 → 0.0042**. But checking sharpness (spread of the recalibrated scores) revealed the fix's real cost:

| | Std. deviation | Range |
|---|---|---|
| Raw combined confidence | 0.131 | 0.162 – 0.833 |
| Platt-recalibrated confidence | 0.031 | 0.644 – 0.812 |

Nearly all predictions collapsed into a narrow band close to the dataset's overall base rate (~76% accuracy). ECE alone doesn't capture whether a score remains *useful* — a model that always predicts the base rate also achieves near-zero ECE while carrying no discriminative information. With only 76 labeled examples, Platt scaling didn't have enough spread in the input data to fit a curve that preserved separation.

**Decision:** used the raw (uncorrected) combined confidence for threshold-based abstention, since it — despite its documented bias — still meaningfully separates confident from uncertain cases, which is what a threshold-based decision actually needs.

## Final validated result

Sweeping thresholds over the 76-question eval set and selecting `threshold_high = 0.60` (the highest threshold keeping coverage ≥ 50%, so the system still answers a practical majority of questions) and `threshold_low = 0.40`:

| Decision tier | n | % of questions | Accuracy |
|---|---|---|---|
| ANSWER | 43 | 56.6% | **88.4%** |
| HEDGE | 30 | 39.5% | **63.3%** |
| ABSTAIN | 3 | 3.9% | 33.3%* |

*Based on only 3 examples — directionally supportive, not statistically robust.

The monotonically decreasing accuracy across tiers is the core empirical validation: when the system says it's confident, it's right far more often (88.4%) than when it would abstain (33.3%). This is the proof that combining three independent signals produces a confidence score that meaningfully predicts correctness — the central premise of the project.

## Honest limitations / Future work

- **Eval set size (76, not 200):** Groq's free-tier daily token limit (200K TPD) was exhausted partway through larger runs; 76 labeled examples is enough to show a clear trend but leaves individual bins (especially ABSTAIN, n=3) statistically fragile. A larger eval set is the highest-value next step, and would likely let Platt scaling (or a full 3-feature learned calibrator) fit without collapsing sharpness.
- **Single-document retrieval:** built on SQuAD 2.0, which pairs each question with one passage — this isolates the calibration problem cleanly but doesn't test multi-document retrieval difficulty.
- **Equal-weighted signal combination:** the three signals are averaged with equal weights as a deliberate, simple baseline — not learned. A logistic regression over the three raw signals (rather than pre-averaged) is a natural next step once more labeled data is available.
- **Hedge tier is non-interactive:** "HEDGE" surfaces an uncertainty-flagged answer rather than an interactive clarifying question, since evaluating a true back-and-forth clarification loop needs a different setup than a static benchmark allows.

## Module reference

### `build_index.py`
Loads SQuAD 2.0 validation split, deduplicates `context` passages into the retrieval corpus, embeds them with `all-MiniLM-L6-v2` (`normalize_embeddings=True`), builds a `faiss.IndexFlatIP` (exact inner-product search — deliberately not an approximate index like HNSW, to avoid introducing index-approximation error into the confidence signal), and persists the index + passage list to disk.

Run once: `python3 build_index.py`

### `retrieval.py`
```python
retrieve(query: str, k: int = 5) -> dict
# returns: {"query", "passages", "scores", "retrieval_confidence"}
```
Embeds the query with the same model/settings as the corpus, searches the FAISS index, and computes `retrieval_confidence` via `compute_retrieval_confidence()`:

```python
combined = gap_weight * score_gap + min_score_weight * top_score
# where score_gap = (scores[0] - scores[1]) / scores[0]
```
Both weights default to 0.5.

### `reranker.py`
```python
rerank(query: str, retrieval_result: dict) -> dict
# returns: {"query", "reranked_passages", "rerank_scores", "rerank_confidence"}
```
Feeds `(query, passage)` pairs to a `CrossEncoder("cross-encoder/ms-marco-MiniLM-L-6-v2")`, re-sorts candidates by the cross-encoder's score. Since cross-encoder outputs are unbounded raw logits (not normalized like cosine similarity), `compute_rerank_confidence()` applies a sigmoid to each score before computing the same gap+top-score formula used in retrieval.

### `generation.py`
```python
generate_answer(query: str, context_passage: str, temperature: float = 0.7) -> str
self_consistency_confidence(query: str, context_passage: str, n_samples: int = 5) -> dict
# returns: {"raw_answers", "majority_answer", "consistency_confidence"}
normalize_answer(text: str) -> str   # SQuAD-style: lowercase, strip articles/punctuation
```
Calls Groq's `openai/gpt-oss-20b` (a reasoning model — `max_tokens=300`, not the default 50, to leave headroom for internal reasoning tokens before the final answer is written; a lower `max_tokens` was found to silently truncate output to an empty string). Samples `n_samples` times at `temperature=0.7`, normalizes each answer, and returns the fraction agreeing with the majority as `consistency_confidence`.

Note: a majority answer that is itself a model abstention ("I cannot answer this...") is a materially different case from a genuine low-agreement answer — both can register as high `consistency_confidence` (all 5 samples agreeing to refuse counts as consistency = 1.0). Downstream consumers (`pipeline.py`) must check for this explicitly; see `is_model_abstention()`.

### `run_eval.py`
```python
run_single_example(example: dict, weights: tuple = (1/3, 1/3, 1/3)) -> dict
check_correctness(majority_answer_raw: str, is_answerable: bool, gold_answers: list) -> bool
is_abstention(answer_text: str) -> bool
run_eval(n_questions: int, eval_set_path: str, output_path: str) -> list[dict]
```
Runs `retrieve → rerank → self_consistency_confidence` per example, computes `combined_confidence` as an equal-weighted average of the three signals, and checks correctness:
- **Answerable questions**: normalized system answer must equal or contain a normalized gold answer.
- **Unanswerable questions**: correct iff the system's answer is itself an abstention.

Wraps each example in try/except so a single failure (network error, rate limit) doesn't abort the whole run; failures are logged and skipped, not silently swallowed.

### `calibration_analysis.py`
```python
compute_reliability_diagram(results: list, n_bins: int = 5) -> (bin_edges, bin_confidences, bin_accuracies, bin_counts)
compute_ece(bin_confidences, bin_accuracies, bin_counts, total_n: int) -> float
plot_reliability_diagram(...) -> None   # saves PNG via matplotlib
```
Bins by `combined_confidence`, computes per-bin mean confidence vs. mean accuracy. Uses 5 bins rather than the conventional 10, given a 76-example eval set — 10 bins would leave several with <5 examples, making per-bin accuracy statistically unreliable. Last bin uses an inclusive upper edge (`<=`) so confidence exactly at 1.0 isn't silently excluded.

### `recalibrate.py`
```python
fit_platt_scaling(results: list) -> LogisticRegression
apply_recalibration(results: list, calibrator) -> list   # adds "recalibrated_confidence" field
compute_sharpness(confidences: list) -> float             # std deviation
```
Fits a 2-parameter logistic regression (`corrected = sigmoid(a * raw_confidence + b)`) mapping raw `combined_confidence` to `P(correct)`. Chosen over a full 3-feature learned calibrator specifically because a 4-parameter model risks overfitting on 76 examples with no held-out set. Not used downstream (see Finding #3) — `pipeline.py` and `abstention.py` use raw `combined_confidence`.

### `abstention.py`
```python
sweep_thresholds(results: list, thresholds: np.ndarray = None) -> list[dict]
# each dict: {"threshold", "coverage", "n_answered", "selective_accuracy"}
choose_thresholds(sweep_results: list, min_coverage: float = 0.5) -> (threshold_high, threshold_low)
make_decision(combined_confidence: float, threshold_high: float, threshold_low: float) -> str
```
`choose_thresholds` selects `threshold_high` as the highest sweep value still meeting `min_coverage` (default 0.5 — a system that abstains on the majority of queries is not practically useful); `threshold_low = max(0, threshold_high - 0.2)`.

### `pipeline.py`
```python
answer_question(
    query: str,
    threshold_high: float = 0.60,
    threshold_low: float = 0.40,
    weights: tuple = (1/3, 1/3, 1/3)
) -> dict
# returns: {
#   "query", "decision", "display_answer", "raw_answer",
#   "combined_confidence", "signals": {...}, "top_passage",
#   "raw_answer_samples"
# }
is_model_abstention(answer_text: str) -> bool
```
The deployable entry point. Composes `retrieve → rerank → self_consistency_confidence`, computes `combined_confidence`, applies `make_decision`, and formats `display_answer` — explicitly distinguishing **model-level abstention** (the LLM itself declined to answer, detected via `is_model_abstention`) from **system-level decision** (the confidence-threshold routing). These are independent: a HEDGE-tier confidence score can co-occur with a model that already gave up on the passage, and the display text must reflect that combination correctly, not assume HEDGE always implies a real candidate answer exists.

Thresholds and weights are parameters, not hardcoded constants — re-running `abstention.py` on a larger eval set only requires updating the defaults here, not touching pipeline logic.

### `demo.py`
Interactive CLI loop around `answer_question()` — prints the decision, the formatted answer, and the full three-signal breakdown for every query, so the reasoning is always visible, not just the final output.

## Known implementation details worth flagging

- **`normalize_embeddings=True`** is required in both `build_index.py` and `retrieval.py` — `IndexFlatIP` computes raw inner product; normalization is what makes that equivalent to cosine similarity. Mismatched normalization between corpus and query embedding silently breaks similarity comparisons.
- **Groq model deprecation**: `llama-3.1-8b-instant` / `llama-3.3-70b-versatile` are deprecated on Groq; `generation.py` uses `openai/gpt-oss-20b`. If Groq's available models change again, `MODEL_NAME` in `generation.py` is the single place to update.
- **`.pkl`/`.faiss` files are build artifacts, not source** — regenerable via `build_index.py`; not intended to be hand-edited or committed as source of truth.
- **Daily API quota**: Groq's free tier caps at 200K tokens/day; a 200-question eval run at `n_samples=5` exceeds this. `eval_results.json` in this repo reflects a 76-question run.
